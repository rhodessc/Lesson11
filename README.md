# Lesson 11: Adding an AI Chatbot to the Weather Dashboard

## Overview

In this lesson, we will add an interactive AI chatbot to our existing Streamlit weather dashboard.

We will use the Groq API to connect to a large language model (LLM) that answers questions about our weather data. Unlike the AI weather report from Lesson 10, the chatbot will allow users to ask specific questions and maintain a conversation.

We will use Streamlit's session state to store conversation history so the chatbot can understand follow-up questions.

1. Create a Python function that sends user questions to an LLM.
2. Explain the purpose of system, user, and assistant messages.
3. Build an interactive chatbot using Streamlit.

5. Pass a pandas DataFrame to an LLM as context.
6. Handle API errors using Python's `try/except` statements.

## Lesson Activities

### Step 1: Create the Chatbot Function

In `ai_report.py`, create a new function named `ask_question()`.

The function will:

- Accept two arguments: `weather_data` and `messages`.
- Connect to Groq using the existing API key.
- Convert the weather DataFrame into text.
- Create a system message instructing the LLM to answer using only the provided weather data.
- Send the conversation history to the LLM.
- Return the model's response.

### Step 2: Understand Conversation Messages

The Groq API uses messages to communicate with the language model.

Each message is a Python dictionary containing two keys:

- `role`: Identifies who is sending the message.
- `content`: Contains the message text.

Our chatbot uses three roles:

- **System:** Provides instructions and weather data to the model.
- **User:** Contains questions entered by the user.
- **Assistant:** Contains answers previously generated by the model.

Conversation messages are stored in a Python list.

For example:

```python
[
    {"role": "user", "content": "What is the highest temperature?"},
    {"role": "assistant", "content": "The highest temperature is 28°C."},
    {"role": "user", "content": "Which city had that temperature?"}
]
```

By passing previous messages to the model, we allow it to interpret follow-up questions in context.

### Step 3: Initialize Streamlit Session State

Streamlit reruns the Python script whenever a user interacts with the application.

To preserve conversation history, we use `st.session_state`.

```python
if "messages" not in st.session_state:
    st.session_state.messages = []
```

`st.session_state` is built into Streamlit, but `messages` is a variable we create.

It contains a Python list of dictionaries representing the conversation.

### Step 4: Add the Chat Input

Use Streamlit's `st.chat_input()` to create an input field where users can enter questions.

```python
question = st.chat_input("Ask About the Weather")
```

When the user enters a question, we append it to the conversation history.

```python
if question:
    st.session_state.messages.append(
        {"role": "user", "content": question}
    )
```

### Step 5: Generate and Store the AI Response

Call the `ask_question()` function using the filtered weather data and conversation history.

```python
try:
    answer = ask_question(
        filtered.tail(50),
        st.session_state.messages
    )
except Exception:
    answer = "Sorry, the chat is not available right now."
```

We use `try/except` to prevent an API error from crashing the Streamlit application.

Next, append the AI response to the conversation history.

```python
st.session_state.messages.append(
    {"role": "assistant", "content": answer}
)
```

### Step 6: Display the Conversation

Use `st.chat_message()` to display previous user questions and AI responses.

```python
for msg in st.session_state.messages:
    st.chat_message(msg["role"]).write(msg["content"])
```

Because conversation history is stored in session state, previous messages remain visible when Streamlit reruns.

## Key Concepts

- **Chatbot:** An application that allows users to interact with an AI model through conversation.
- **System Message:** Instructions that guide how the LLM should respond.
- **User Message:** A question or request submitted by the user.
- **Assistant Message:** A response generated by the LLM.
- **Conversation History:** Previous messages passed to the model to provide context.
- **Session State:** Streamlit's mechanism for preserving variables across application reruns.
- **Context:** Information supplied to an LLM to support its responses.
- **Exception Handling:** Using `try/except` to handle errors without terminating the application.
